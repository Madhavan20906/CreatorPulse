# CREATORPULSE — MASTER BUILD PROMPT

## 0. ROLE

You are a senior AI product architect, full-stack engineer, AI-agent engineer, UX engineer, and hackathon-winning product builder.

Build a production-quality MVP called **CreatorPulse**.

The target hackathon is an **AI Content Engine Hackathon** whose goal is to build tools that automate some part of the creator workflow.

The project will be judged primarily on:

* Functionality
* Real-world usefulness
* Creativity
* Technical execution

Therefore, do NOT build a fake AI dashboard, static prototype, collection of disconnected AI generators, or UI-only demo.

The application must perform genuine work.

The core philosophy is:

> **CreatorPulse does not merely generate content. It learns how a creator's content performs, determines what the creator should create next, produces the content package, validates it, and uses the resulting performance to improve future recommendations.**

The central product loop is:

```text
CONNECT CHANNEL
      ↓
UNDERSTAND CREATOR
      ↓
ANALYZE CONTENT
      ↓
UNDERSTAND AUDIENCE
      ↓
IDENTIFY OPPORTUNITIES
      ↓
RECOMMEND WHAT TO CREATE
      ↓
GENERATE CONTENT
      ↓
QUALITY-CHECK CONTENT
      ↓
CREATOR APPROVAL
      ↓
PUBLISH / SCHEDULE
      ↓
COLLECT PERFORMANCE
      ↓
COMPARE PREDICTION VS ACTUAL
      ↓
UPDATE CREATOR MEMORY
      ↓
IMPROVE NEXT RECOMMENDATION
      ↓
REPEAT
```

This feedback loop is the central differentiator.

# 1. PRODUCT NAME

## CreatorPulse

### Tagline

> **Your autonomous content growth loop.**

Alternative short description:

> **Turn every upload into a smarter content strategy.**

Primary pitch:

> CreatorPulse is an AI-powered creator operating system that analyzes a creator's existing content, discovers content opportunities, generates platform-specific content, validates it before publishing, and continuously learns from real performance to improve the creator's next move.

# 2. CORE PROBLEM

Creators spend enormous amounts of time on work surrounding creation:

* deciding what to create
* researching topics
* checking whether an idea overlaps existing content
* identifying clips
* writing scripts
* creating titles
* writing descriptions
* generating captions
* creating hashtags
* adapting content for different platforms
* preparing thumbnails
* checking SEO
* checking publishing readiness
* scheduling content
* analyzing performance
* figuring out why something performed well
* deciding what to create next

Existing tools often solve these problems independently.

CreatorPulse should connect them.

The product should answer:

> **"Given everything this creator has already published and everything we know about their audience, what should they do next—and can we execute it?"**

# 6. TECHNOLOGY STACK

Use a practical, hackathon-friendly architecture.

Recommended:

## Frontend

* Next.js
* React
* TypeScript
* Tailwind CSS
* shadcn/ui
* Recharts or equivalent charting library

## Backend

* Python
* FastAPI
* Pydantic
* SQLAlchemy

## Database

Prefer PostgreSQL.

Use SQLite only as a fallback for local/demo environments.

## AI

Use a strong LLM API for:

* reasoning
* classification
* strategy
* content generation
* quality analysis
* explanation

Do not use the LLM for deterministic tasks that can be performed with normal code.

## Video/audio

Use appropriate real media-processing libraries such as:

* FFmpeg
* Whisper-compatible transcription

## Authentication

For the MVP:

* simple secure authentication
* OAuth where practical
* YouTube OAuth for real channel connection if credentials are available

## Background processing

Use:

* Celery + Redis

OR a simpler async job queue if time constraints make Celery excessive.

Do not introduce infrastructure merely for appearance.

# 7. DESIGN PRINCIPLE

Use AI where reasoning is required.

Use deterministic code where deterministic behavior is possible.

For example:

GOOD:

```text
LLM:
"What topics are emerging from this creator's videos?"
```

GOOD:

```text
Python:
"Calculate average views by topic."
```

GOOD:

```text
Python:
"Calculate CTR difference."
```

BAD:

```text
LLM:
"Calculate 30-day average views."
```

The architecture should demonstrate thoughtful engineering.

* embeddings
* topic similarity
* keyword overlap
* semantic similarity

```text
"5 AI coding agents every developer should use"

Similarity with existing content:

Video #12 → 81%
Video #28 → 74%
```

```text
REFRAME

"AI Coding Agents vs Copilots:

```

Understands individual content.

Chooses the best next action.

### 6. Script Agent

Generates long-form content.

### 7. Repurposing Agent

Creates Shorts/social variants.

### 8. SEO Agent

Optimizes discoverability.

Checks content.
